# 新词雷达：免费来源日报

使用 [new-term-radar](https://github.com/zhuyansen/new-term-radar) 的免费采集器，保留上游 MIT 许可证；上游代码取自 3cf6515c4076cb2800819473062d9b36d563d0fe。每天北京时间 08:00 执行，公开 `public/latest.json`。采集仅针对公开来源，不调用 AIsa、GoAnyAPI、TrustMRR 等付费接口。来源错误和首次建立快照会在报告中标记。

GitHub Actions 缓存保存来源快照；缓存被清理后，部分来源需要重新建立基线。报告内容公开可访问，不应放入私有信息或密钥。

数据流画布可展开查看每一环节的规则、来源状态和少量公开数据样本。新增的采集过程记录从部署后的下一次采集开始产生；旧报告未保存的原始数量和淘汰原因不会被补造。为控制公开报告大小，各来源只保留少量示例，非完整原始数据。

必要时可手动运行“单独采集流程明细”。它使用已有的来源对照进行一次独立采集，只发布 `public/flow-diagnostic.json`，不保存这次对照，也不覆盖 `public/latest.json`；因此过程明细的时间和数字可能与日报不同。页面会标明数据来自独立采集还是日报，并优先使用时间较新的过程记录。

## Stack Exchange 用户需求

每日读取最近 7 天的 Software Recommendations 问题，以及 Stack Overflow、Super User、Web Applications 中标题包含 automate 的问题。沿用上游 `asks.stack_all`、`asks.stack_sites`、`asks.stack_titles` 默认配置；每个社区最多读取 3 页，每页 50 条。逐条保留标题、作者、原文和许可证，按社区与问题编号去重。候选词是规则清理后的标题，不代表已经验证的新词、搜索量或付费需求；搜索和趋势入口需要人工核验。

每个来源独立记录失败；接口要求等待时遵守其 backoff，结果分页达到上限时标记不完整。页面只展示最近七天，并非完整历史记录。此流程不调用原项目中收费的模型分类、搜索量和竞争分析。

## 同行 Sitemap 监控

网站的“新增网址明细”逐条展示从上一次对照后首次发现的网址，保留来源、所处内容清单、雷达首次发现时间，以及从网址提取的候选词。Google Trends 的 7 天、30 天、90 天入口和 Google 搜索入口均需手动查看，不代表系统已经确认搜索量或竞争强度。首次发现时间不等于网页发布时间；网址中的文字也不保证是新词。

每个内容清单各自保存对照，并避免将已在同一同行的其他清单中出现过的网址重复算成新增。新网站、新清单或修改监控范围先建立对照；某个来源采集失败时保留它的旧对照。自动过滤分类、标签、作者和归档等路径；站点目录索引默认只选择文章、产品、工具、游戏或页面类子清单，也可以设置筛选规则。仅支持同一网站域名下的内容清单，不支持嵌套索引或需要登录的网站。遵循 robots.txt 及抓取间隔；个别网站可能阻止访问。明细保留最近 30 天，最多 5,000 条。

页面的“同行管理”可直接查看运行状态。管理员通过 GitHub 验证码登录后可在页面修改名单；登录应用限本仓库的 `free-config.json` 单文件权限。登录信息只保存在当前页面内存。也可直接在 GitHub 修改 `free-config.json` 中的 `sitemaps`。保存后下一次采集生效；暂停或移除不会删除近期已发布的明细。请勿将令牌写入配置、仓库或公开报告。
